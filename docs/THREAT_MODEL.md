# Threat Model

## Protected assets

- user files outside the selected input;
- credentials, cookies, tokens, browser profiles, and environment variables;
- network and local services;
- integrity of the original input;
- integrity and provenance of generated artifacts;
- application availability under adversarial input.

## Untrusted inputs

- `.lua`, `.luau`, `.txt`, and `.luac` contents;
- filenames and selected paths;
- malformed bytecode lengths/counts;
- deeply nested syntax and huge literals;
- recovered strings containing HTML, SVG, paths, or terminal control text;
- future sidecar output.

## Non-negotiable controls

- No Lua/Luau execution in the foundation release.
- No `load`, `loadstring`, `dofile`, executor, Python extension import, native
  library load, or generated shell command.
- Original bytes are hashed before decoding and copied unchanged.
- Inputs are never overwritten.
- Exports go to a newly created job directory.
- Accepted input extensions and maximum 10 MiB input size are enforced.
- Input paths are normalized before policy checks. Managed artifacts and bundled
  renderer files are resolved through `realpath` and must stay inside their
  application-owned roots; output names are generated by the application.
- Lua 5.1 bytecode depth, prototype, instruction, constant, and debug-table
  counts are bounded before allocation.
- Source AST size is checked immediately after parsing. Source parsing is
  isolated behind worker heap and wall-clock ceilings; it is not claimed as a
  streaming parser-time node limit.
- Workers receive a minimal environment and are terminated on timeout/cancel.
- Future child processes use exact executable paths and argument arrays with
  `shell: false`.
- Renderer: `nodeIntegration: false`, `contextIsolation: true`,
  `sandbox: true`, restrictive CSP, no webviews, no remote content, blocked
  navigation/new windows, and validated IPC senders.
- Source text is rendered as text, never injected as HTML.
- Every artifact listed in the manifest is hashed before renderer exposure.

## Known limitation

A Node worker process is a resource and fault-isolation boundary, not a full
Windows security sandbox. Because the implemented worker never evaluates the
submitted language or loads submitted native code, this is acceptable for the
static foundation. Any future loader capture or native sidecar requires an
additional OS/WASM sandbox and an explicit security review.

## Supplied encrypted Python archive

The supplied archive contains a stripped Linux CPython 3.12 native extension
that decrypts a hidden payload and evaluates Python bytecode after receiving a
separate key. It is unrelated to Lua deobfuscation, cannot run natively on
Windows, has no supplied license/provenance, and was not executed. It is
excluded from source, builds, fixtures, and sidecar allowlists.
